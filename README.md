# WorkForce Manager

A web platform that connects people who need skilled labor - electricians, plumbers, carpenters, and other tradespeople - with verified local workers. Users can browse worker profiles, filter by profession/location/rating/availability, book a worker, track the job through to completion, and leave a rating. Workers manage their own profiles and bookings, and admins moderate the whole system.

Built with **PHP** and **Oracle Database (PL/SQL)**. The PHP data layer uses the **OCI8** extension; Apache/PHP are served via **XAMPP**.

## Features

### Roles
- **User** - browse and book workers, confirm job completion, leave ratings. No approval required.
- **Worker** - create a profile, receive and manage bookings, mark jobs as done. Requires admin approval before going live.
- **Admin** - approve/reject worker applications and profile edits, manage users and workers, broadcast notifications. Predefined accounts only (no self-registration).

### Booking lifecycle
`pending` -> `confirmed` -> `awaiting_user` -> `completed` (or `cancelled` at any point before completion).

1. User sends a booking request (`pending`).
2. Worker approves (`confirmed`, worker becomes *busy*) or rejects (`cancelled`).
3. Worker marks the job done (`awaiting_user`).
4. User confirms completion (`completed`, worker becomes *available* again) and can leave a 1-5 star rating.

### Other
- In-app notification system with an unread badge and dropdown panel.
- Worker profile edits are queued for admin approval (admins see a before/after diff, including skills).
- Workers can list multiple skills via a chip-style input at sign-up and when editing their profile.
- Logged-in users can save their own location and jump straight to workers near them.
- Image uploads for worker profile photos.
- Password-strength validation on sign-up.
- Responsive dark-themed UI (Syne + DM Sans).

## Tech stack
- PHP with the **OCI8** extension (named-bind prepared statements)
- **Oracle Database** (11g/XE 18c/21c) - schema and constraints in PL/SQL
- Vanilla HTML/CSS/JS - no framework
- Served under Apache via XAMPP

## Setup

1. **Install Oracle Database** (Oracle XE is fine) and create an application schema/user, e.g.:
   ```sql
   CREATE USER workforce IDENTIFIED BY workforce;
   GRANT CONNECT, RESOURCE, CREATE VIEW TO workforce;
   ALTER USER workforce QUOTA UNLIMITED ON USERS;
   ```

2. **Create the schema.** Connect as that user (SQL*Plus or SQL Developer) and run the script:
   ```sql
   @oracle_schema.sql
   ```
   This creates all 6 tables plus the sequences and triggers that emulate auto-increment.

3. **Enable OCI8 in PHP.** Install the Oracle Instant Client, then in `php.ini` enable the
   extension (e.g. `extension=oci8_19`) and restart Apache. Verify with `php -m | findstr oci8`.

4. **Configure the connection** in [`db_connect.php`](db_connect.php): set `$oracle_user`,
   `$oracle_pass`, and `$oracle_dsn` (e.g. `localhost/XE` for XE 11g, `localhost/XEPDB1` for XE 21c).

5. **Create the admin account.** Passwords are bcrypt hashes generated by PHP
   (`password_hash('YourPassword', PASSWORD_BCRYPT)`). Insert one admin row (the id is filled
   automatically by the trigger):
   ```sql
   INSERT INTO admins (name, email, password)
   VALUES ('Super Admin', 'admin@workforce.com', '$2y$10$REPLACE_WITH_A_BCRYPT_HASH');
   COMMIT;
   ```

6. **Open the app** at `http://localhost/DB/`.

## Notes on the Oracle conversion
- Auto-increment is emulated with a `SEQUENCE` + `BEFORE INSERT` trigger per table.
- MySQL `ENUM`s become `VARCHAR2` columns with `CHECK` constraints.
- `TINYINT(1)` -> `NUMBER(1)`, `VARCHAR` -> `VARCHAR2`, `TEXT` -> `CLOB`, `DECIMAL` -> `NUMBER`.
- New ids are returned via `INSERT ... RETURNING id INTO :new_id`.
- The session date format is set to ISO on connect so PHP `strtotime()` can parse timestamps.
- OCI returns `NUMBER` columns as strings, so id values are cast to int where strict
  comparisons are used (e.g. session uid vs `worker_id`).

## Security notes
- Passwords are hashed with bcrypt (`password_hash` / `password_verify`).
- All database queries use named-bind prepared statements (no string-interpolated SQL).
- Access is gated per role on every protected page.
